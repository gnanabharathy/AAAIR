# Running the DQD (Data Quality Dashboard)

This guide is for adding new datasets to the DQD pipeline — running the ETL and quality checks yourself. If you only want to browse DQD results that are already in this repo, you do not need any of this: just run `python3 api.py` and open the web UI (see main README).

**Pipeline:** `etl_v2.py` (loads NHANES data into an OMOP CDM table) → `dqd.R` (runs ~4,000 automated quality checks) → results appear in `dqd/raw/`, `dqd/mapping/`, `dqd/results/`, viewable via `api.py` + the web UI, or directly with `viewDqDashboard()`.

---

## Prerequisites checklist

- [ ] R (>= 4.0.0)
- [ ] Java (>= 8)
- [ ] PostgreSQL running locally
- [ ] Python 3.9+ with `pandas`, `psycopg2-binary`, `pyreadstat`
- [ ] A NIM API key (see main README) — `etl_v2.py` uses this to generate OMOP mappings

---

## 1. Install R and Java

```bash
brew install r
brew install openjdk
java -version   # confirm 8 or higher
```

## 2. Install R packages

In R or RStudio:

```r
install.packages("remotes")
install.packages("DatabaseConnector")
remotes::install_github("OHDSI/DataQualityDashboard")
```

If `DatabaseConnector` fails to load due to `rJava`, confirm Java is installed and reinstall:
```r
install.packages("rJava")
```

## 3. Download the JDBC driver

```r
library(DatabaseConnector)
downloadJdbcDrivers("postgresql", pathToDriver = "jdbc")
```

This populates the `jdbc/` folder (gitignored, machine-specific). Check that `dqd.R`'s `pathToDriver` value points to this folder's **absolute path** on your machine — it's currently hardcoded, so update it if your project lives somewhere else.

## 4. Set up PostgreSQL and create the OMOP CDM schema

Start Postgres and create a database:
```bash
createdb omop
```

Generate and run the OMOP CDM 5.3 DDL directly from R (creates all the standard CDM tables in an empty schema):
```r
install.packages("devtools")
devtools::install_github("OHDSI/CommonDataModel")

cd <- DatabaseConnector::createConnectionDetails(
  dbms = "postgresql",
  server = "localhost/omop",
  port = 5433,
  user = "omop_user",
  password = "omop_pass",
  pathToDriver = "jdbc"
)

CommonDataModel::executeDdl(
  connectionDetails = cd,
  cdmVersion = "5.3",
  cdmDatabaseSchema = "public"
)
```

Adjust `server`, `port`, `user`, `password` to match your actual Postgres setup — the values above match what's currently in `dqd.R`.

You'll also need at least one row in the `CDM_SOURCE` table describing your dataset — `DataQualityDashboard` reads this for the JSON output metadata. `etl_v2.py` should populate this as part of the ETL step; if it doesn't yet, insert a row manually before running DQD.

## 5. Install Python dependencies

```bash
pip install pandas psycopg2-binary pyreadstat --break-system-packages
```

Also make sure `.env` has a valid NIM API key (see main README, Step 2).

---

## 6. Run the pipeline end to end

**Single dataset:**
```bash
python3 etl_v2.py nhanes-demographics-demo_i-2015
Rscript dqd.R nhanes-demographics-demo_i-2015 "NHANES Demographics 2015-16"
```

**Batch (skips datasets already completed):**
```bash
python3 batch_etl_dqd.py --category demographics
```

If everything is set up correctly, you should see:
```
[DQD] Starting nhanes-demographics-demo_i-2015
[DQD] Done: dqd/raw/nhanes-demographics-demo_i-2015.json
[DQD] Log moved to: dqd/results/log_DqDashboard_NHANES Demographics 2015-16.txt
```

## 7. View the results

**Option A — via the project's web UI:**
```bash
python3 api.py
```
Then open `http://localhost:8765` and navigate to the dataset — `api.py` reads the JSON from `dqd/raw/`.

**Option B — directly in R:**
```r
DataQualityDashboard::viewDqDashboard("dqd/raw/nhanes-demographics-demo_i-2015.json")
```
This opens an interactive Shiny app showing pass/fail results by check category.

## Output structure

```
dqd/
├── raw/       # DQD JSON results, one per dataset — read by api.py and viewDqDashboard()
├── mapping/   # OMOP mapping JSON generated by etl_v2.py
└── results/   # DQD run logs (log_DqDashboard_*.txt)
```

## Troubleshooting

- **`rJava` fails to load / `.onLoad failed`** — Java version mismatch. Confirm `java -version` shows 8+, close all R sessions, and reinstall `rJava` and `DatabaseConnector`.
- **"No drivers matching pattern found in folder"** — the `jdbc/` folder is empty or `pathToDriver` in `dqd.R` doesn't match its real location. Re-run `downloadJdbcDrivers()`.
- **DQD runs but `api.py` returns 404** — check the file actually landed at `dqd/raw/{ds_id}.json` and that `ds_id` in the URL matches the filename exactly.
- **`executeDdl` fails with permission errors** — the Postgres user needs `CREATE` privileges on the target schema.
- **CDM_SOURCE table empty** — `viewDqDashboard` and the JSON output will still work, but source metadata will be blank; insert a row before running DQD for cleaner output.
